# TypeScript 编写规则

## 适用范围

- `apps/**/*.ts`
- `apps/**/*.tsx`
- `packages/**/*.ts`
- `packages/**/*.tsx`

## 角色定位

TypeScript 只负责前端界面、状态管理、以及调用 Rust IPC 的薄桥接。

## 分层规则

### `apps/*`

1. 只放应用页面、页面状态拼装、页面级交互。
2. 不重复实现 Rust 已有业务策略。

### `packages/shared`

1. 放共享类型、IPC 封装、枚举、桥接常量。
2. 页面不要绕开这里去直接写底层命令字符串。

### `packages/ui`

1. 放通用组件、布局壳、跨应用共用视图。
2. 组件保持展示职责，不承载后端策略。

## 代码规范

1. 固定标识、命令枚举、事件枚举统一收敛到共享层。
2. 展示文案走 i18n，不把业务文案散落在组件里。
3. 优先消费共享类型，不在页面里重复定义接口。
4. 不在前端重复解析后端业务规则，前端只消费结果。
5. 保持 IPC 调用薄，不在调用层叠加大量策略判断。

## React 规则

1. 优先写清晰的状态流，不滥用过度抽象。
2. 组件复杂时拆出小组件，但避免无意义碎片化。
3. 只有在确有必要时才加性能优化钩子。

## 注释要求

1. 只给复杂数据流、复杂桥接逻辑、复杂 UI 状态机写注释。
2. 注释优先解释“为什么”，不是解释显而易见语法。

## IPC 规则

1. 所有后端调用优先通过 `packages/shared` 封装。
2. IPC 返回类型要显式，不使用无约束的 `any` 扩散。
