# Python 编写规则

## 适用范围

- `channel_agent/**/*.py`

## 角色定位

Python sidecar 只负责：

- `wx` / `wework` SDK 登录与回调
- SDK 消息解析
- SDK 消息发送
- SDK 媒体下载与必要格式转换
- `rust_ipc` 双向通信
- `markitdown` 文档转 Markdown

Python sidecar 不负责：

- 应用编排
- 前端 API 路由
- 配置持久化策略
- AI Agent 业务逻辑
- 模型提供商逻辑
- 调度、任务、工作流

## 代码规范

1. 能放 Rust 的逻辑，不放 Python。
2. 能删除的中间层就删除，不保留“以后可能还会用”的抽象。
3. 一个模块如果只被一个地方使用，优先内联。
4. 不新增与渠道无关的“通用框架层”。
5. 不新增测试脚本、复现脚本、旧控制台路由脚本。
6. 不新增旧渠道兼容代码，只允许保留 `wx` 与 `wework`。

## 模块边界

1. `wechat_channel.py` / `wework_channel.py` 只处理各自渠道的运行时行为。
2. `wechat_message.py` / `wework_message.py` 只处理各自渠道的消息解析。
3. `run.py` 只处理 `ntwork` 客户端初始化、注册、运行循环。
4. `rust_ipc.py` 只处理 Rust 通信，不承载业务规则。
5. `rpc_handlers.py` 只做最小 RPC 分发，不写策略层逻辑。
6. `stdio_server.py` 只做 sidecar 启动，不写编排策略。
7. `config.py` 只保留运行时所需最小配置。

## 函数与类

1. 关键函数必须写中文文档注释。
2. 文档注释至少说明：
   - 功能
   - 关键参数
   - 返回值
3. 小型辅助函数可以不写长注释，但命名必须清晰。
4. 类职责必须单一，不允许一个类同时承担 SDK 适配和应用编排。

## 错误处理

1. SDK 调用失败时，要返回可诊断的错误信息。
2. 不要静默吞掉异常，除非明确是“尽力而为”的状态通知。
3. 日志优先输出事实，不输出空泛语句。

## 风格要求

1. 默认使用简单直接的同步/线程模型，不引入不必要复杂度。
2. 保持 ASCII 优先，只有原文件已有中文或渠道文案时再跟随。
3. 不为兼容旧设计保留双路径实现。
